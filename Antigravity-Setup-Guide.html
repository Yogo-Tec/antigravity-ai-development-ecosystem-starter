Your AI Development Headquarters

A reusable Google Antigravity ecosystem for websites, e-commerce, mobile apps, community systems, office/club platforms, plugins and custom software.

Final setup: One central GitHub repository is the source of truth. Copy only selected skill folders into each project's .agents/skills/. Do not rely on undocumented manifest inheritance.

Tests, code review, security, staging and approved release.

4. Windows installation

  1. Create a private GitHub repository and push the starter kit.
  2. Clone it to a stable path such as C:\AI\antigravity-ai-development-ecosystem.
  3. Open PowerShell in the clone and run:
.\scripts\install-profile.ps1 -ProjectPath "C:\Projects\MyWebsite" -Profile website

Open the project in Antigravity. Ask it to inspect AGENTS.md and .agents/skills/, list discovered skills and prepare a plan before coding.

The installer preserves existing skills and AGENTS.md. It does not install external software or overwrite existing instructions.

7. Safety and controlled automation

  • Review third-party skill code, licenses and install scripts.
  • Use least-privilege tool permissions.
  • Never expose secrets in code, logs or prompts.
  • Ask before paid services or external sharing of private data.
  • Ask before destructive migrations, data deletion, production permission changes, protected-branch pushes or production deployment.
  • Require tests, staging verification and rollback planning before release.

8. Implementation roadmap

  1. Create and populate the central GitHub repository.
  2. Test project-local skill discovery in Antigravity.
  3. Install the website profile in a sample project.
  4. Validate the skill library and add CI checks.
  5. Curate upstream skills after license/security review.
  6. Add domain-specific skills only when needed.
  7. Configure MCP servers individually with least privilege.
  8. Tag stable releases and document updates.

9. First Antigravity prompt

Read AGENTS.md and inspect .agents/skills/.

Identify the project type, goals, existing stack, constraints and missing requirements. List the skills actually discovered and select only those relevant. Do not assume tools, MCP servers or integrations are installed unless verified.

Prepare a plan for requirements, architecture, UI/UX, implementation, tests, security and deployment. Identify risks and approval points. Do not make destructive changes, install system tools, expose secrets or deploy to production without explicit approval.

Wait for approval before major implementation. At each milestone report changed files, tests actually run, results, limitations and next steps.
